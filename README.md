# Startup scripts dedicated to Minecraft Forge (1.17+), NeoForge, and Fabric servers

## Written in PowerShell

### Currently for personal use, so the Java path is hardcoded

### The following section (most likely) needs to be modified before use:

```powershell
# Absolute path to Java
$JavaPath = "C:\Program Files\BellSoft\LibericaJDK-$($Minecraft.JavaVersion)-Full\bin\java.exe"
```

## Usage

A very simple command-line invocation method. You can modify the loader (including type), Minecraft version, and Java version simply by changing parameters.

Example:

```powershell
pwsh .\Start-ForgeServer.ps1 -Version 26.1.2 -Loader NeoForge -LoaderVersion 26.1.2.22-beta -JavaVersion 25 -ImmediatelyExit
```

```powershell
pwsh .\Start-FabricServer.ps1 -Version 26.1.2 -LoaderVersion 0.19.2 -JavaVersion 25 -ImmediatelyExit
```

Both Forge and Fabric require the Minecraft version and loader version to be specified. For Forge-based servers, you must also specify whether to use the Forge or NeoForge loader.

The Java version defaults to 25 if not specified.

Features include automatic detection/download/installation of loaders based on parameters, seamless EULA agreement within the terminal, and support for the `-ImmediatelyExit` parameter to exit the script immediately after the server shuts down.

The Forge/NeoForge side detects Minecraft and loader versions based on the content of the path where `win_args.txt` is located and checks for the existence of `user_jvm_args.txt` before startup.

The Fabric side detects the Minecraft version by parsing the `version.json` content within `server.jar`. Loader version detection relies on the `fabric-loader-xxx.jar` filename. It checks for the existence of `fabric-server-launcher.jar` and `server.jar` before startup.

Starting from 26.1-snapshot-1, the Fabric side uses the unmapped version by default, removing `intermediary-xxx.jar`. Since the Minecraft version can no longer be determined via filename, it is retrieved by parsing `server.jar`.
